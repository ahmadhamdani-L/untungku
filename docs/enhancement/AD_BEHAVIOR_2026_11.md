# Ad behavior enhancement — 2026-11-09

User requested small native templates in the product list every three items, odd-input interstitials, app-resume app-open ads, and rewarded feature unlocking. User selected six extras with a 30-minute session unlock. This supersedes the previous reward-only quiet-time Settings placement in ALL_AD_FORMATS.md.

- Product catalogue: SDK small native template after visible filtered/sorted products 3, 6, 9, etc. Stable product-based slot keys. Only the active catalogue instantiates slots, and screens below 360 logical pixels omit them so the 40-pixel page padding leaves the recommended 320-pixel minimum. Existing Reports template retained. SDK attribution/AdChoices, consent, privacy invalidation and no-fill backoff retained.
- New product saves: confirmation appears only after the database save succeeds. The Selesai boundary counts committed new products 1, 2, 3, etc.; only odd inputs may show a preloaded interstitial. Edits, validation errors, CSV import, stock adjustments and archive actions do not enter this counter. Counter advances even when ads are unavailable or suppressed. No delayed display after loading. Existing initial two-minute grace, three-minute shared spacing, five/session cap, foreground/consent checks and other transaction completion placements remain.
- App-open: first qualifying warm resume is now eligible, removing the prior two-return skip. Existing Beranda-only safe-route check, at least 30 seconds backgrounded, no keyboard/PIN, opaque resume overlay, preload-only boundary, four-hour expiry, ten-minute cooldown and two/session cap retained. Cold starts and ad-generated lifecycle transitions do not trigger it.
- Reward gates: advanced cashflow reports (CashReportsPage), business insights, price calculator, product CSV import, receipt customization and printer settings. Public feature entry widgets cover alternate navigation routes. Printer and receipt sections are gated individually in their shared settings page. Basic dashboard, sale/expense/product entry, stock, cash accounts/transfers, customers/suppliers, receivables, PIN, backup/restore and receipt viewing/sharing remain accessible.
- Each gate discloses all six extras and the duration, then requires an explicit cancellable Tonton iklan confirmation. The confirmation route finishes closing before presentation. Only one SDK earned callback per presentation grants access to all six extras. Dismissal, consent denial, no fill and failed presentation do not unlock. Availability is shown, retry is offered and core functions remain accessible offline. Unlock does not mute other ads.
- Entitlement is memory-only, ending after 30 minutes or process termination. Background time counts toward expiry. An already-open tool stays authorized so expiry never interrupts an import/print/form. Leaving and reopening after expiry requires a new earned reward. Development builds with live ads disabled bypass gates without initializing the SDK; production offline/no-fill does not bypass them.

No dependency, schema, financial posting, package identity, signing key, production App ID or production ad-unit changes. No production ad requests during development.

References: [Google small native templates](https://developers.google.com/admob/flutter/native/templates), [rewarded earned callbacks](https://developers.google.com/admob/flutter/rewarded), [app-open lifecycle and expiry](https://developers.google.com/admob/flutter/app-open).

Validation and remaining device/build evidence are recorded in PROGRESS.md and TASKS.md. This change does not itself declare release readiness or publish a binary.
